# Runtime and source-truth boundaries

These obligations remain runtime responsibilities. Their existence is not a claim of a missing route, a scope exception, live brokerage validation or Principal Product acceptance. The finite implementation/test mapping is in [coverage.json](coverage.json); the original R01–R19 contract obligations remain in the [accepted review register](../../reviews/api-v2-foundational-contract-2026-10-20/runtime-invariants.md).

- Source truth is not established by JSON Schema or a typed reference. A producer must demonstrate the predicate, Account, subjects, quantities, time and source guarantee appropriate to each claim. A native complex parent/child record corroborates instructions; alone it does not establish current financial membership, historical occurrence, a current atomic OCO group, execution guarantee, reserved shares or closure.
- A compatible repeated custody observation is not an event. Unique compatible UNRESOLVED inventory scopes retain their GUID with qualified continuity. Ambiguous/overlapping/incompatible active scopes are not merged, split or guessed. CLOSED is terminal; later observed exposure can have a new GUID without an invented opening date. An unobserved intervening close/reopen remains unknowable.
- Account-wide conservation and aggregate fungible coverage require all applicable current-cut resources. Schema cannot add cross-resource quantities or prove exclusive allocations. Unknown source quantities and competing claims qualify affected Positions and Constructions. Unallocated inventory is not buying power or broker reservation.
- Immutable instance/version resolution and immediate same-Position/Account predecessor checks are persisted runtime invariants. Instance history records Wheelwright's retained interpretation history, not missing brokerage events or universal split/recombine semantics.
- Named recognition requires independently admitted membership as well as compatible roles, quantities and exact immutable Model definitions. Reference enrichment does not manufacture membership. Unsupported recognition preserves actual constituents; generic mathematics can remain available independently.
- Financial values require their actual sign, units, currency, multiplier, deliverable, source clocks, horizon and cost/fee attribution. Standard common-expiration exact intrinsic geometry is supported; missing basis can preserve terminal rights without inventing gross-profit break-evens. Unsupported adjusted/mixed-horizon economics remain qualified/unavailable. Current quotes never replace missing historical evidence.
- Original/current/cumulative comparisons retain documented terms and interval cash evidence. Interval completeness is not automatically lifetime history. Expired/replaced protection is historical; unknown/adjusted/incompatible deliverables or currency cannot establish current share protection. Tax basis, realized attribution and discretionary basis policy are not invented from cash sums.
- Token User and Account capabilities apply through direct reads, collections, links, expansions, source evidence, history and Audit. Restricted Order-derived opening clocks, original DTE, metric asOf/currency, warnings, management, history and profit geometry cannot survive redaction. Independently supported contractual terminal geometry may remain. Shared reference data cannot expose private Account/upload references.
- Read/import/synchronization success is distinct from complete financial truth. Failed source contact can leave a valid200 read with warnings and prior retained facts. A missing/unusable body is not fabricated as an Artifact. Broad instructions and complex corroboration have separate outcomes; one cannot mask the other's failure.
- Broker contact policies remain default-off and Account-authorized. Tests use repository or explicitly synthetic loopback evidence and temporary databases. Production credentials, deployment, installed grants, actual Account source availability and load beyond tested finite budgets are not verified here.

Portfolio membership, first-class Executions, universal split/recombine, discretionary basis allocation, operator-association tooling and independent synchronization-job identity remain explicitly open/deferred. They have not been selected to make this implementation appear complete. No ww live work is included. Independent Kiro verification and Principal backend acceptance precede client integration.

Successor authorization clarification: Account-wide inventory reconciliation requires both Account Position-read and holdings-read, because total custody quantities/residuals are independently protected. A transaction-derived fill/evaluation metric requires its Account transaction-read capability in addition to any Order grant; redaction removes value, asOf and currency while independently reported Order fill price/time remain inspectable. Source Artifact access separately controls raw evidence links. These are runtime enforcement obligations, not guarantees from JSON Schema.

R1/R2 refinement: see [source predicates](r1-r2/evidence-map.md) and [current exposure](r1-r2/reconciliation.md). A uniquely corroborated current closing-instruction scope plus independently observed exact inventory can support qualified current financial composition, while leaving occurrence origin unknown. Aggregate owned coverage is a separate calculation. Neither admits a historical opening from matching legs. Current exposure, lifecycle, source completeness and last-reported Order status remain distinct. New schema restrictions constrain representation shape only; finite runtime tests exercise the source predicates and cross-Account enforcement.
