## 4. Implementation expectations and candidate fitness

These apply the selected architecture; they do not prescribe every implementation.

- **SDK conformance:** native SDK execution owns general conversation/tool iteration.
  Host code may handle UI, credentials, trusted projection, policy configuration,
  lifecycle and bounded SDK extensions. An `Agent` calling an old question router is
  nonconforming. Inspect real call paths and behavior, not just forbidden-string scans.
- **MCP conformance:** admitted capabilities and schemas come through supported MCP
  discovery/integration, with configuration/policy admission and backend grants.
  A native tool that bypasses MCP for Wheelwright domain operations does not conform.
  This is not a ban on HTTP inside MCP adapters, model transport, authentication wiring,
  ordinary host helpers or capability-specific presentation. Preserve safe problem
  identity, evidence qualifications, subject and API/trace correlation. An MCP error
  must not become an invented connection failure or unsupported recovery capability.
- **Financial/UX integrity:** only backend-established conclusions may populate the
  presentation's authoritative findings. Commentary must not rewrite those findings or
  acquire their authority through placement, styling or persistence. It can perform the
  newly permitted hypothetical reasoning. Existing result/resource references can ground
  findings; no universal claim-ID registry is necessary. Validate subject, units,
  economic role and source qualifications, including purely qualitative commentary.
  Numeric membership cannot detect “77% reward/risk” becoming a confirmed probability.
- **Privacy/security:** configure the normal runtime before first exposure, not only
  test mode. `store:false`, local session storage and disabled trace export address
  different paths. A local session passed to remote compaction still discloses its
  history and is prohibited. Local transcripts remain non-authoritative conversation
  records, not a competing financial datastore or current grants. Context replay must
  stay within the authorized User/data scope; secrets remain outside model-visible
  inputs. Existing scoped real-data permissions are preserved without requiring a new
  general ZDR decision or treating that permission as blanket clearance.
- **Failure handling:** preserve validated, still-authorized evidence on commentary
  failure. Do not display an unauthorized or invalid result merely because a table was
  previously available. Missing evidence/capability, missing authority and execution
  failure require distinct grounded treatment. A gap does not authorize a new tool.
