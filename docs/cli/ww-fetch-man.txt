NAME
    ww fetch — acquire canonical direct quotes for named subjects

SYNOPSIS
    ww fetch [-q | --quiet | -v | --verbose] [--force] [--] SYMBOL...
    ww fetch --help | -h | --man

DESCRIPTION
    Fetch satisfies a direct-quote acquisition request through Wheelwright
    API v2. At least one explicit symbol is required. Bare fetch is a usage
    error and performs no API or provider work. There is no default selector.

    Symbols are uppercased and deduplicated in first-occurrence order, retaining
    the existing CLI operand convention. All subjects are submitted together
    in one POST /v2/quotes request. The backend accepts at most 30 distinct
    subjects; larger requests fail as a whole, without automatic splitting.
    Malformed subjects are diagnosed by the backend. Unsupported well-formed
    subjects receive independent per-subject outcomes.

    Ordinary fetch sends mode ORDINARY. The backend may reuse eligible held
    evidence or acquire it upstream. --force sends mode FORCE, bypassing reuse
    and requesting an actual upstream acquisition attempt. Backend authorization
    and contact restrictions still apply. Fetch never retries automatically.

    The backend owns reuse eligibility, session identity, provider compatibility,
    contact policy, subject verification, persistence, authority fencing, and
    acquisition truth. Fetch expresses intent and renders the returned facts.
    It does not enroll subjects in Decision or traverse expirations or chains.

OPTIONS
    -h, --help
        Show command help. Use alone after fetch, without execution flags
        or symbol operands.

    --man
        Show this manual. Use alone after fetch.

    --force
        Request FORCE acquisition. Requires backend quote.force authorization
        in addition to quote.acquire. Prior evidence cannot satisfy FORCE.

    -q, --quiet
        Suppress normal human status. Failures still appear on stderr.
        Structured result records and exit status are unchanged.

    -v, --verbose
        Show all per-subject outcomes, Wheelwright endpoint, request correlation,
        mode, and fulfillment count on stderr even when redirected.
        Quiet and verbose are mutually exclusive. Verbose does not show prices.

    --
        End option parsing. Remaining arguments are symbol operands.

OUTPUT
    Terminal stdout is empty. Normal terminal stderr identifies every outcome:

        SPY: NEWLY_ACQUIRED
        QQQ: REUSED
        fetch complete: 2/2 fulfilled; 1 newly acquired, 1 reused, 0 failed

    NEWLY_ACQUIRED means the backend accepted authoritative quote evidence.
    REUSED means existing evidence satisfied ORDINARY policy; it does not mean
    a provider acquisition. Neither outcome certifies trading suitability.

    Any unfulfilled subject makes fetch fail, even if prior evidence remains:

        SPY: FAILED UPSTREAM_FAILED; prior quote retained (request unfulfilled)
        fetch failed: 0/1 fulfilled; 0 newly acquired, 0 reused, 1 failed

    Safe backend failure detail may follow the outcome. Failures remain visible
    under --quiet and when stderr is redirected. Mixed results retain each
    subject's outcome; there is no overall success message for partial failure.

    Piped/redirected stdout emits one fetch-result/v2 JSON Lines record per
    subject, including failures. Each record includes symbol, subject, outcome,
    fulfilled, observation, priorRetained, optional failure, requestId, mode,
    startedAt, and completedAt. Backend observations, facts, identity, provenance,
    and original clocks are preserved. Missing quote facts are not synthesized.
    Operation clocks are distinct from observation and source-event clocks.
    Rich domain evidence justifies retaining the existing JSON Lines convention.

    Request-wide errors emit stderr diagnostics with the backend code, safe
    explanation, correlation, and validation details when supplied. They emit
    no per-subject records. Transport and malformed-response errors also fail.
    Credential values are redacted from server-provided output.

EXIT STATUS
    0   Every requested subject was fulfilled (NEWLY_ACQUIRED or REUSED).
    1   Any subject unfulfilled, request/transport/response failure, or missing
        or invalid Bearer credential.
    2   Invalid command usage or invalid endpoint configuration.

    Exit codes do not encode HTTP status codes or individual acquisition outcomes.

ENVIRONMENT
    WW_BASE_URL
        Wheelwright endpoint; default http://localhost:3100. HTTPS is required
        outside loopback development. Embedded URL credentials are rejected.
        Redirects are rejected to avoid forwarding credentials elsewhere.

    WW_API_TOKEN
        Explicit Bearer credential configured for a Wheelwright principal,
        exported or stored as WW_API_TOKEN in the repository private .env file.
        Nonempty exported values override the file. Only this
        one file key is read; shell substitutions are never executed.
        Missing/empty credentials fail before contacting the backend. No anonymous
        fallback, hard-coded token, or trusted-local bypass exists. The backend
        checks quote.acquire and, for FORCE, quote.force. ww does not provision
        tokens or infer grants, and never prints the credential.

EXAMPLES
    ww fetch SPY
    ww fetch SPY QQQ IWM
    ww fetch SPY --force
    ww fetch -v SPY QQQ
    ww fetch -q SPY > quote-acquisition.jsonl

EVIDENCE LIMITS
    ww prices remains an independent v1 read of chain-associated underlying
    price evidence. It does not inspect the direct quotes acquired by v2 fetch.
    ww ls quotes discovers current canonical v2 holdings without acquisition.
    Its summaries omit detailed quote facts; inspect the fetch JSON Lines
    observation for this acquisition request's canonical direct quote.
