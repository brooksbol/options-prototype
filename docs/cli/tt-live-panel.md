# tt live compact panel

Principal-approved October 11, 2026; implementation candidate, manual acceptance separate.
Standalone tastytrade companion only. No Wheelwright v2 Position, order-writing or management-rule changes.

## Approved contract

Human columns: SYMBOL, PAYOFF, EXP, QTY, DTE, EXIT Pxx, EXIT DTE, OPEN, NOW, TARGET, P/L, SPOT, QUOTE.
One row per recognized position; masked account and expiration year in heading. Mixed expiration years appear in each EXP value. Broker position order is preserved.

OPEN is weighted actual opening-fill net credit. NOW preserves the existing sum of short leg broker mids minus long leg mids. TARGET is the verified broker debit limit. P/L is `(OPEN - NOW) * quantity * multiplier`, gross before fees. Partial-close accounting remains unsupported. Profit exit progress is signed `100 * (OPEN - NOW) / (OPEN - TARGET)`; negative and over-100 results are retained. `~` denotes indicative mid at/below target while still held, never execution. P50:B requires actual 50% gross credit capture; other exact integer credit-capture objectives use their own Pxx:B label; noninteger objectives use LIMIT:B and the numeric TARGET. T flags an existing exit transition; `tt positions` retains broker target/stop details. No DTE exit is inferred. DTE retains New York calendar-date counting floored at zero.

SPOT is exclusively tastytrade equity `mid`, inside validated nonnegative bid/ask, with a valid quote-update timestamp and positive midpoint. No last, mark or close substitution. This is a quote observation timestamp, not a trade-event timestamp. Missing, duplicated or malformed equity observations produce unknown spot; valid option economics survive. Stale spot retains a numeric value plus `!` but cannot supply an active marker. Eligible retained spot can supply a marker.

O/S label independent option/spot observations. Human QUOTE uses elapsed ages: seconds below 60, whole minutes below 60 minutes, then whole hours (10s, 10m, 10h), rounded down. Each age carries its own r/! suffix. TSV retains its existing date/age conventions. O uses the oldest leg. `r` identifies eligible broker-confirmed latest-completed-session observations, including shortly after close. They are not official closing prices. Ordinary 12-hour freshness is unchanged; session lookup failure retains age-only behavior. Missing evidence is `—`, stale is `!`. There is no leg timestamp-skew bound or persistence fallback. Provider evidence limit remains 100 held option symbols; equity reads are separate bounded requests.

## Terminal behavior

Default width comes from stdout, then COLUMNS, then 157; `--width 20..1000` overrides it. Every invocation checks width, including watch refreshes after resizing. Fixed PAYOFF width is 31 cells. Numeric fields right-align; financial values are never truncated. A narrow view drops PAYOFF, OPEN, TARGET, then SPOT as necessary, retaining identity, exit, P/L, progress and independent evidence. An impossibly narrow view explicitly reports the number of positions not displayed and directs the operator to TSV. Layout reserves the last terminal cell.

ANSI is excluded from cell counts; combining sequences and wide graphemes are measured. Apple Terminal ambiguous-width line glyphs are treated as one cell. `--no-color`, nonempty NO_COLOR or TERM=dumb disables color; `--ascii` (also TERM=dumb) provides ASCII. Normal human output continues emitting ANSI through pipes for watch -c. The Principal removed the bottom legend; explanations remain in CLI help and this reference. Static economics remain neutral; current P/L uses sign colors; profit progress uses the exit-track semantics below, evidence uses amber/gray. No whole-row coloring or bullish/bearish desirability colors.

TSV retains the existing schema, ordering, optional NOTE, calculations and quote-label semantics. It acquires no new spot evidence. PAYOFF uses the approved line silhouette; block-height rendering was explicitly rejected by the Principal.

## PAYOFF geometry

The trading projection verifies every leg against broker instrument terms: Standard chain, 100 deliverable shares, 100 holding multiplier, matching underlying, right, strike and expiration. No adjusted-contract support is inferred. Missing or conflicting terms produce `IC [?terms]`; existing recognition failures still abort the whole command. Terms use the existing broker batch instrument lookup with a four-concurrent single-contract fallback if the batch route fails. TSV makes neither instrument nor underlying reads. Production verification found batch HTTP 403 and successful single-contract reads.

The 31-cell allocation reserves one indicator cell and uses a 30-cell linear plot spanning long-put strike minus 10% of outer strike range through long-call strike plus 10%. Every strike and valid spot uses that same axis. Strike locations round to the nearest cell; maximum coordinate error is half a cell. Wings/plateau narrower than one cell, or collapsed rounded boundaries, yield `IC [compressed]` rather than enlarged wings. Exact contract strikes remain in `tt positions` broker evidence.

Tails use `_`, slopes `╱`/`╲`, plateau `‾`; ASCII uses `_`, `/`, `\`, `-`. A wing's occupied cells follow its actual span; repeated slope strokes indicate a longer wing. Unequal wing widths retain their horizontal proportions and carry a `≠` prefix (ASCII `U`). One-row tail levels communicate regions, not equal dollar loss: numerical economics remain separate. Principal refinement October 11: use bright red for negative expiration tails, bright yellow/amber for slopes and evidence, bright green for the maximum-profit plateau and positive economics, bright cyan for the valid midpoint marker, and bright white for reference values. Loss tails no longer use ANSI dim, for visibility on a black background. No current-profit inference comes from the plateau. The graphic remains available when option quotes go stale because it describes expiration shape.

Spot uses the exact validated observation shown in SPOT. Fresh or eligible retained spot positions `▼` (ASCII `v`); stale/missing spot supplies no marker. Spot beyond the plotting interval uses an outward arrow (ASCII `<`/`>`), never a silently clamped location. Spot outside the long strikes but inside the interval remains proportionally positioned on its loss tail.

Final verification: 45/45 relevant Node tests pass, including proportional and unequal/narrow wings, missing/stale/retained spot, off-chart arrows, unsupported terms, bounded instrument fallback, twenty aligned graphics, semantic colors and no block characters. Read-only production Sunday output draws verified EWZ/XLE shapes while independently showing stale underlying records and retained option economics. Apple Terminal visual acceptance remains separate from deterministic cell and PTY checks.


## Exit-progress extension — October 11, 2026

Baseline: main `368335c`; PRs #35, #36 and #37 verified merged. This extension remains a separate PR for review. The normal `tt` launcher stays on main until review/merge; preview this branch explicitly.

Headers always read `EXIT Pxx` and `EXIT DTE`, even for homogeneous positions, so mixed objectives cannot be mislabeled by a shared P50 heading. Per-row profit prefixes use `P50:B`, another exact integer capture objective such as `P60:B`, or `LIMIT:B` for a noninteger capture fraction. Numeric TARGET remains authoritative. `B` denotes the verified broker limit; `T` replaces B during an existing exit-order transition. Recognition and target/stop linkage constraints are unchanged. Missing target linkage still fails the command closed; the renderer can show an unavailable objective but does not introduce partial portfolio rendering.

Profit progress is `(OPEN - NOW) / (OPEN - TARGET)`, not the fraction of original credit captured. At P50, 25% credit capture is 50% target progress. Opening credit comes from actual fills, NOW from validated broker leg mids, TARGET from the matched broker profit-limit order. Stale option evidence makes the track unavailable while preserving the verified objective label. Retained eligible option evidence remains usable, independently of spot.

The track is nine terminal cells, left = opening state, right = observed profit threshold. A cyan `●` marks ordinary progress; amber marks progress from 90% up to the threshold. This is a presentation cue, not a management rule. Negative progress uses a red outward `←` at the left edge. Threshold reached uses a green `◆` plus `~`, meaning indicative midpoint at/below target while still held. The signed percentage remains explicit and unbounded, including below zero and above 100%; only marker position is bounded. Neither green nor the diamond asserts broker execution. Above 100%, an outward green `→` at the right edge explicitly distinguishes exceeded progress even when the percentage rounds to +100%. ASCII uses `-`, `o`, `<`, `>`, `*`. Labels, tracks and percentage right edges align across rows; ANSI never contributes to cell width.

No authoritative time-exit objective exists in tt acquisition, configuration or projection. The XSP research D21 rule is unrelated and supplies no policy for these positions. `EXIT DTE` therefore renders gray `— no rule` (ASCII `-- no rule`) for every row. Expiration and broker stop-limit orders are not time-exit objectives. Opening DTE is available in the domain projection from verified latest opening-fill timestamp and expiry using the existing New York calendar-date convention; it does not create a management objective. Enabling a real time track requires an authoritative, position-linked declared objective and provenance. Once such support exists, the required interpretation is `(opening DTE - current DTE) / (opening DTE - exit DTE)`, with explicit handling of invalid denominators and due/overdue states. Declared-DTE approaching/due/exceeded and mixed-DTE-threshold scenarios remain unsupported, deliberately unimplemented and unclaimed by these tests.

The full layout budgets 156 terminal cells, including separators and independent quote evidence, within a 157-column terminal with the last cell reserved. Nine-cell tracks keep all approved economics and the unchanged 31-cell PAYOFF graphic on the row at normal values. Financial precision and large signed percentages may expand widths; deliberate narrow fallback then omits PAYOFF/OPEN/TARGET/SPOT in the existing order rather than wrapping or truncating. Very narrow terminals explicitly refuse the panel. The bottom legend remains removed; bright black-background colors remain unchanged, including PAYOFF tails, slopes, plateau and spot.

Extension verification: 53/53 relevant Node tests pass. A read-only production Sunday run also preserves retained option valuations and independently stale spot evidence. Verification adds profit scenarios at 0%, 40%, 50%, 90%, 100%, negative and over 100%; target absence/fail-closed behavior; stale valuation; exact differing broker targets; unavailable DTE policy and New York opening DTE; age boundaries; ASCII/monochrome colors; and twenty mixed progress rows at 157/189 columns. Existing weekend, PAYOFF, acquisition and narrow-view regressions remain in the suite. TSV was compared byte-for-byte against baseline main for normal, weekend-retained, stale, empty and transitional-order fixtures. No acquisition routes, schemas, order rules or Wheelwright v2 interfaces change.
