## Reconciliation: existing authority and genuinely new commitments

Existing authority already covers question-driven Product development; backend-owned financial semantics and evidence; one v2 API with many clients; authorized user/data boundaries; complexity earned, recover/reuse/compose before invent; versioned ADR/knowledge ownership; graduated architectural fitness controls. Do not mint duplicates.

**New Principal direction requiring precise architectural disposition:** an SDK-based new Talk and a pause on further bespoke one-off Talk development. The pause is a sequencing directive, not acceptance/rejection of candidate code or permission to mutate installations. Existing original MCP-learning purpose and host independence remain relevant; using an SDK in one host does not mandate that other hosts use the SDK or MCP.

**Candidate operational standards for ratification review** (industry sources are support, not Wheelwright authority):
- **Decision determinacy:** for a consequential architectural choice, implementing actors recover binding precedents, identify viable native/framework and custom alternatives, document constraints and trade-offs, and identify the accountable decision authority before a durable divergence. Do not prescribe a chosen pattern where justified alternatives exist.
- **Framework leverage:** default to reviewing available supported framework mechanisms before reimplementing generic agent loops, sessions, tool discovery, tracing or recovery; custom behavior is permitted with evidence of need, privacy, security, economics or Product fit. The Principal's SDK choice for *new Talk* is a scoped technology directive, not a general vendor mandate.
- **Reusable capability boundary:** backend owns authoritative financial state, evidence and governed conclusions; MCP faithfully exposes independently meaningful capabilities without duplicating calculations; SDK host owns generic conversational execution, tool admission and context/presentation. Do not mandate one tool per question or speculative tool catalogs.
- **Trusted semantics and disclosure:** authorization and financial claims are not enforced by prompts/schema alone. Trustworthy financial assertions must preserve backend claim identity, subject, provenance and qualifications. Whether free conversational arithmetic/financial interpretation is allowed and the applicable model disclosure profile are open Product decisions to resolve before relevant acceptance.
- **Observable fitness:** evaluate real operator questions through bounded API/MCP/host specimens; preserve useful errors, correlation, partial evidence and actual subject continuity; test negative security/semantic cases. Controls begin observational and earn promotion through the existing Technology Quality Constitution; no automatic CI gates.

Potential falsifiers: actor cannot tell who owns an architectural decision; two actors independently make durable incompatible choices without flagging missing authority; new tool requires question-specific host source code; API v2 422 loses safe problem identity or request correlation; a model presents an indicative credit as a confirmed fill or wrong financial probability; confidential result is exported through tracing/compaction; conversation narration fails and otherwise established evidence disappears; new process delays operator feedback without measurable gain.

SDK selection does not prove conformance to privacy or financial-authority boundaries; default SDK tracing/compaction/session egress requires explicit evaluation. Native SDK must not be mistaken for an authoritative financial engine.

### Four subsequent settled Principal decisions (details under mandates 3–4)

1. **SDK + MCP:** The OpenAI Agents SDK, not the raw Responses API loop, executes the general conversation/tool cycle for new Talk. Wheelwright domain tool access is through the SDK's supported MCP integration, using discovered tool contracts and trusted admission controls; ordinary UI and security adapters are allowed. Dependency presence alone is insufficient proof.
2. **Restrictive disclosure:** Automatic trace export disabled; local conversation state; no provider-managed conversation storage or remote compaction; `store:false` where applicable; existing scoped real Account-data permissions respected. Broader exposure needs explicit Principal approval **before** data enters model requests, trace/session storage, compaction or other external processing. Configuration and egress must eventually be verified.
3. **Authoritative facts plus commentary:** Backend-established financial facts and conclusions remain authoritative; model may provide clearly qualified hypothetical arithmetic, analysis and alternatives without transforming commentary into established findings. UX must make the distinction **implicitly understandable by information hierarchy and visual design**; exact UX design is deferred. A numerical whitelist or probabilistic judge alone cannot guarantee semantic integrity. Validated evidence survives commentary failure.
4. **Deprecated bespoke Talk:** Indefinitely paused Product branch, preserved as valuable learning, not a target for further conversational feature additions. No cleanup or runtime action is implicit.
