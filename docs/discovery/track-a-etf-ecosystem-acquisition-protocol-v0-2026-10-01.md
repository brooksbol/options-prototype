# Track A ETF ecosystem acquisition protocol v0 — proposed

**Status:** Category E draft for PR #32, 2026-10-01. This specifies a future observation; it authorizes no provider call, census, ETF score, candidate decision, specimen, or production change. Read with the [Track A schema](track-a-etf-option-ecosystem-observation-schema-v0-2026-10-01.md), [ETF cohort](pass-minus-one-etf-cohort-and-tradier-ecosystem-view-2026-10-01.md), frozen [Pass −1](pass-minus-one-v0-occ-tradier-identity-snapshot-2026-10-01.md), and adopted [Pass 0](pass-zero-v1-class-geometry-method-2026-10-01.md). Scope is exactly the **1,643 Cboe-labeled ETF underlyings and their 1,766 OCC class rows**; the parent 6,072/6,381 counts remain visible. Other product tiers are outside this protocol.

## RAW ACQUISITION

### Wave, slots, dates, and denominator

A **wave** is one declared attempt to observe all 1,766 class rows. Before its first request, persist the source/cohort hashes, one `wave_class_ledger` row per class, a deterministic partition manifest, named market dates and planned slot start/end in both `America/New_York` and UTC, the named/versioned US equity-session calendar, provider environment, parser/protocol versions, and a SHA-256 of the manifest. A wave is a dated *series*, never a simultaneous cohort snapshot. Each underlying and all its OCC classes belong to exactly one partition/run. An unattempted partition retains all its ledger rows. There is no implicit make-up date or replacement run.

For initial planning, partition underlyings by ascending SHA-256 of the UTF-8 string `source_population_sha256|occ_underlying`; greedily add the next whole underlying to a partition while its archived cost `4 + count(unique same-date/future expiration dates across its archived lookup roots)` remains at most **750 baseline request starts**. A single underlying exceeding the cap gets its own partition. This cost is for scheduling only and never affects ecosystem evidence or class state. Freeze the resulting partitions and their explicit calendar slots before any acquisition. Plan each partition for a **30-minute slot wholly within regular US equity trading hours**, with slots on as many declared trading dates as required. Do not infer that members of different slots or dates share a market condition. A later wave may use a newly declared schedule, but cannot silently rewrite this one.

The scheduled `observation_market_date` is the New York date assigned in the manifest; the **actual observation market date** for each request/body is the New York date of response receipt. Keep UTC request start and receipt, planned slot boundary, source-side bid/ask/trade timestamps, and Greek update string/time independently. `market_session_phase` is the planned slot's local time label plus independently recorded actual regular/pre/post/closed/unknown state, not a freshness claim. A request begun within the slot but received outside it is retained with `RECEIPT_AFTER_SLOT`; a request begun outside is retained with `START_OFF_SLOT`. If any bodies cross the local date boundary, split date-specific class/expiration/contract rollups, mark `DATE_BOUNDARY_CROSSED`, and do not collapse them into one observation date. No new request or retry starts after the slot end; remaining work stays `UNATTEMPTED` and requires a separately declared future wave to revisit. Preserve first/last request and provider timestamp ranges so later analysis can quantify asynchrony.

### Request order, scope, and immutable evidence

Use one shared production market-data pacer across the worker, including retries: at most **119 request starts in any trailing 60 seconds**. Record rate-limit headers, `Retry-After`, transport timing, endpoint, exact query parameters, status, original response headers/body or transport error, raw-body SHA-256, parser version, and source JSON pointer for every decoded row. Store each attempt separately and hash-verify before derivation. If a shared pacer cannot be guaranteed, do not start the wave. The accepted [backend invariant](../foundations/backend-behavioral-invariants.md) uses the 119/minute production pacer; the [Tradier rate-limit reference](https://docs.tradier.com/docs/rate-limiting) documents the 120/minute production market-data allowance.

For each assigned underlying, use the explicit Pass −1 query symbol/alias edge, then request: (1) exact underlying option-symbol lookup to observe all returned roots; (2) the all-root expiration endpoint, preserving every returned date/root/type/size field and raw order; (3) one underlying quote bundle; (4) one daily underlying history bundle; (5) one `greeks=true` chain for **each deduplicated same-date or later date** in the union of parsed dates from lookup symbols and the expiration endpoint. Request chains by underlying/date and preserve every returned root; classify contracts only against their exact frozen OCC class. Query dates in ascending order. One chain may supply evidence for multiple exact classes, but no root is silently normalized. A chain does not inherit exact-class identity merely because the queried underlying matches. Retain anomalous, duplicate, conflicting and unparseable expiration entries in `expiration_listing`; preserve the source-request edge. The all-root query and its parameters must be logged verbatim, including `includeAllRoots=true` where supported. Endpoint disagreement is an explicit catalog-conflict state, not a reason to take an intersection.

All provider-listed **same-date and later** expiration dates require a chain attempt for a complete ecosystem observation. There is no DTE window or sampled-expiration shortcut. A past-dated entry is preserved as an anomaly but does not trigger a chain request. An invalid date cannot be silently ignored: it prevents catalog completeness until explained. A listed date with failed chain retrieval keeps an `expiration_acquisition` row and makes affected class geometry incomplete. A parseable empty chain is `VALID_EMPTY` and is not an HTTP failure; if lookup listed contracts at that date, mark source conflict as well. A returned chain with another root only is evidence of exact-root absence for that date, contingent on complete response. Duplicate date entries produce one chain request, with all original entries retained. Distinct metadata for the same date is a conflict, not silently deduplicated away. Missing a provider-listed future date is never interpreted as an unoptionable product.

### Bounded attempts

A logical request gets at most **three attempts total** (initial plus two), and only attempts starting before its slot ends. Use a 20-second client timeout. For network/transport errors, timeout, HTTP 5xx, or HTTP 200 with malformed/unparseable required JSON, wait 2 seconds before attempt two and 8 seconds before attempt three. For HTTP 429, honor the provider `Retry-After` if parseable; otherwise stop new requests for 60 seconds under the shared pacer, then retry within the same three-attempt cap and slot. HTTP 4xx other than 429 is terminal for that logical request; 401/403 also halt the wave pending authorization diagnosis. A valid empty body with documented empty representation, identity mismatch, missing expiration, null/zero quote field, or absent exact root is semantic evidence and does **not** trigger retry. If the provider's empty representation is not parseable under the frozen parser, classify it malformed rather than silently treating it as empty. Every failed attempt and eventual success remains separately referenced; a retry never overwrites history. Time/budget exhaustion leaves explicit `UNATTEMPTED` or `FAILED` states. No acquisition failure becomes “not optionable.”

### Underlying reference and terms

The reference source is Tradier market-data quote and daily history for the same explicitly queried underlying/provider alias as the option requests. Capture one quote and one history **per underlying/run** and link their immutable `reference_id` to every assigned class; do not copy apparently identical quotes into independent class facts. The quote stores its request start/receipt UTC, provider trade/bid/ask timestamps when present, raw values, and query symbol/alias edge. The history request uses `interval=daily`, `start = scheduled market date minus 400 calendar days`, `end = scheduled market date`, inclusive as requested; store exact requested dates, returned first/last dates, every returned bar date/value, missing dates relative to the declared session calendar separately from closed dates, headers/body/hash, and any provider adjustment metadata. This bounded raw-history envelope is **not** an adopted RV window, reference-price rule, or assertion that 400 days suffice for future Pass 1 replay. Because Tradier's documented history interface does not establish a corporate-action adjustment convention here, mark `adjustment_convention=UNVERIFIED_PROVIDER_SEMANTICS` unless separate source evidence is attached. Do not calculate returns across an unexplained split/distribution discontinuity or claim quote freshness from field presence. Quote/history gaps only affect ancillary reference states, never Pass 0 geometry.

Record Tradier `contract_size` as raw evidence. An OCC class is `VERIFIED_STANDARD` or `VERIFIED_NONSTANDARD` only with source-dated, contract-matched authoritative terms; otherwise `UNVERIFIED`, even when `contract_size=100`. A cash component such as the prior TSLL1 evidence cannot be inferred from that field. Terms gaps remain visible without excluding the class.

### Same-date expirations

If `expiration_date = actual observation_market_date`, request and retain the chain when provider-listed. Its calendar `dte_days` is **0**. Store listing/strike geometry, quotes and quote-side times separately; assign `expiration_session_state` from actual timestamp and an explicit authoritative cutoff when available, otherwise `CUTOFF_UNVERIFIED`. Date equality alone does not prove the contracts remain tradeable or have expired during the session. A later analysis may declare an inclusion rule; raw acquisition makes none. If a slot/date boundary changes which date is same-day, retain both scheduled and actual-date classifications with lineage.

## COMPLETENESS

Completeness is **not** a quality score. For each class, keep one primary acquisition status (`COMPLETE_RAW`, `PARTIAL`, `UNATTEMPTED`) plus independent deficiency flags and attempt counts. `COMPLETE_RAW` requires a resolved exact class/root, parseable lookup and all-root expiration catalogs, and a parseable terminal chain result for every required same-date/future date; an empty exact-root chain counts as observed absence, not a failed request. Contradictory or unparseable catalog/contract identity prevents complete class geometry. Market field `ABSENT`, `NULL`, numeric zero, crossed quotes, and old provider timestamps remain faithfully observed values, not acquisition failures. `market_evidence_incomplete` means a required chain body or required quote-field decoding provenance is absent/unusable, **not** that a market failed a liquidity test.

Independent flags are `IDENTITY_UNRESOLVED`, `CATALOG_INCOMPLETE_OR_CONFLICT`, `GEOMETRY_ACQUISITION_INCOMPLETE`, `MARKET_EVIDENCE_INCOMPLETE`, `REFERENCE_QUOTE_INCOMPLETE`, `REFERENCE_HISTORY_INCOMPLETE`, `TERMS_UNVERIFIED`, `REQUEST_FAILURE`, `OFF_SLOT`, and `DATE_BOUNDARY_CROSSED`. Store a set of reason codes, not one exclusive verdict. `COMPLETE_RAW` may coexist with reference or terms flags: only identity and complete class-specific geometry determine the adopted Pass 0 structural state. A class with exact root absent in a **complete** response is an observed identity/geometry state; a class whose relevant request failed is unresolved acquisition, not observed absence. Cohort completeness requires all 1,766 ledger rows accounted for and individually complete, with attempted/unattempted and exact-state counts also reported across all 1,643 underlyings. A partial wave remains analyzable with explicit denominator and timing gaps.

## DERIVATION

After hash verification, derive exact-class/right/strike/expiration geometry, DTE, quote-field presence/value states, independent side ages and Greek update ages, and all same-class/same-expiration put-pair quote-side states using only the formulas and rollups in the [schema](track-a-etf-option-ecosystem-observation-schema-v0-2026-10-01.md). Preserve raw rows, duplicate identities, source conflicts, explicit nulls and zeros. Derived row keys include run/date, exact OCC class/root, provider contract symbol and source pointer. Report per-class expiration acquisition counts and per-wave timing ranges; a missing later request is unknown, not ecosystem deterioration.

## ANALYSIS DEFERRED

No observed spread, size, OI, volume, delta, quote freshness, synthetic pair price, or package quality selects a contract or changes acquisition completeness. This protocol defines no good/bad ETF, cutoff, score, ranking, candidate set, selected expiration/strike pair, capital-risk model, persistence judgment, or Exit Reliability inference. Those require separately declared later methods and repeated/execution observations.

## Offline request-budget check

From the **archived 2026-10-01 option-symbol lookups only**, the 1,643 ETF underlyings collectively had **8,342 unique same-date or future underlying×expiration dates** across returned roots: 8,336 strictly later and six same-date (`GLD`, `IWM`, `QQQ`, `SMH`, `SPY`, `XLF`). Counting separately by exact OCC class would produce 8,549 class/date associations; one all-root chain per underlying/date avoids 207 duplicate requests while retaining class-specific interpretation. These are planning counts from a dated lookup, not predictions of a future endpoint's complete response. Future newly listed dates, catalog disagreement, timeouts and retries can increase the request count; no finite upper bound follows from this archive.

| Component | Baseline requests for one wave |
| --- | ---: |
| Underlying/root lookup | 1,643 |
| All-root expirations | 1,643 |
| Underlying quote | 1,643 |
| Daily history | 1,643 |
| Same-date/future chains | 8,342 |
| **Total baseline** | **14,914** |

Chains are ~56% of baseline. At 119 starts per rolling minute, **about 125.3 minutes** is only a pacing lower bound for request starts; latency, slot boundaries, retries and rate-limit responses add time. Three attempts for every baseline request would mean 44,742 starts before any newly observed expirations; it is a mechanical ceiling for that *fixed baseline set*, not an expected count or a hard wave upper bound. The 750-start partition cap yields approximately 20 half-hour slots on the archived cost model, but actual partition manifest, market dates and capacity must be frozen before a future authorization. Do not quietly sample expirations to fit an operational budget.
